# 作業の着手

このリポジトリは**複数のエージェントセッションが同時に走る前提**で運用されている。
着手手順が固定されているのはそのため — メインツリーで直接作業すると、他セッションと
HEAD を奪い合い、自分のコミットが他人のブランチに乗る。

## 手順

### 1. Wiki を読む

コードを grep する前に `wiki/index.md` を読み、関連ページに当たりを付けて読む。
過去の経緯・却下された代替案・踏むと壊れる落とし穴はそこにある。ここを飛ばすと、
一度否定された設計を再提案したり、既知の罠を踏み直したりする。

```bash
cat wiki/index.md
```

**`recurring-review-findings` は毎回読む。** レビューで繰り返し差し戻された誤りの種類がまとまっている。
作業の領域に関係なく当てはまるので、関連ページとして拾えなくても読む。

**末尾の「未作成ページ」節も読む。** そこは「まだ書かれていないページ」の控えであると同時に、
**他セッションが書くと宣言したページ名の予約台帳**でもある。これから作るページが載っていたら、
その名前に合わせる(同じ概念のページを別名で二重に作らないため)。

### 2. 対応 Issue を確保する

open Issue に同じ話が既にあるかを先に見る。重複起票は履歴を分断するので避ける。

```bash
gh issue list --repo kant0123/MeltKelp --state open --limit 30
```

**既にある** → その番号を使う。新しく分かった事実があればコメントで足す。

**無い** → 起票する。**これから作るものの仕様・受け入れ基準は Issue 本文に書く**
(設計書は作らない。`wiki/` は「今どうなっているか」の記録であって、これから作るものの
仕様書ではないため)。

```bash
gh issue create --repo kant0123/MeltKelp --label <bug|enhancement|documentation|...> \
  --title "<一文で何をするか>" \
  --body "<背景 / 対象ファイル(path/to/file.cs:123 形式) / 受け入れ基準>"
```

秘匿情報(トークン・鍵・Webhook URL・`config.local.*` の中身)は private リポジトリでも
本文に書かない。ユーザーが打った文字列・Meltype のログも書かない(例文は自分で用意する)。

**Issue は `kant0123/MeltKelp` に立てる。** 上流 (yksr-melt/Meltype) の不具合でも上流には報告しない
(CLAUDE.md「フォークの不変条件」)。

### 3. worktree を切る

```bash
git fetch origin
git worktree add ../MeltKelp-<作業名> -b <branch> origin/main
```

- ブランチ名は `fix/` `feature/` `chore/` `docs/` のいずれかを前置する。
- **ローカル `main` ではなく `origin/main` から切る。** ローカル main は他セッションのマージに
  追いついていないことがあり、そこから切ると古い土台の上に積んでしまう。
- **`upstream/main` から切らない。** 上流の取り込みは `upstream-sync` スキルの手順で行う。
- **ローカルドライブ(C:)に置く。** imev では、ネットワークドライブ・UNC パスで Mozc のビルドが通らず、
  管理者の PowerShell からはネットワークドライブが見えなかった
  (`wiki/operations/build-install.md`)。
- 置き場所はリポジトリの**外**の兄弟ディレクトリ。リポジトリ内(`.claude/worktrees/` 等)には
  作らない — テストやツールの探索対象に入り込み、削除し忘れると
  `git worktree list` に載らない孤立ディレクトリとして残り続ける。

以降の編集・コミットはすべて `../MeltKelp-<作業名>` の中で行う。

## 着手後に効いている制約

作業中ずっと守る必要があるもの。詳細は `CLAUDE.md`。

- **メインツリーで作業しない**(`checkout` で別ブランチに切り替えない)。メインツリーは main のまま、
  マージ後の `git pull --ff-only origin main` だけに使う。
- **上流のファイルとの差分を最小にする。** 機能は新しいファイルで足し、上流のファイルは差し込み口だけ変える。
- **`git add` はファイルを明示指定する。** 他セッションの未コミット変更が混ざりうるため、
  `git diff --cached` で確認してからコミットする。
- **スコープ外の問題を見つけたら、その場で `gh issue create --repo kant0123/MeltKelp` する。** 今の作業は中断しない。
  チャットに書いただけでは記録に残らず失われる。対象・粒度・本文の書き方は `file-issue` スキル。

実装が固まったら `wiki-ingest`、PR 作成以降は `pr-finish` に進む。
